# FitTrack Hub
 
A personal fitness tracking web application for logging workouts, monitoring progress, and building consistent exercise habits. Built with React and Tailwind CSS.
 
## What It Does
 
FitTrack Hub lets you record your workouts day by day, track your personal bests, and see how your consistency trends over time. The interface is minimal by design so that logging a session takes less than a minute and never gets in the way of actually working out.
 
## Getting Started
 
You need Node.js 18 or later installed on your machine.
 
Clone the repository and install dependencies:
 
```
git clone https://github.com/your-username/fittrack-hub.git
cd fittrack-hub
npm install
```
 
Start the development server:
 
```
npm start
```
 
The app will be available at http://localhost:3000.
 
To build for production:
 
```
npm run build
```
 
The output will be in the `build` folder, ready to be deployed to any static host.
 
## Project Structure
 
```
src/
  components/     Reusable UI pieces shared across pages
  pages/          Top-level page components (Dashboard, Log, History, etc.)
  hooks/          Custom React hooks for shared logic
  context/        Global state management via React Context
  utils/          Pure helper functions (date formatting, calculations, etc.)
  styles/         Global CSS and Tailwind configuration overrides
public/           Static assets served as-is
```
 
## Tech Stack
 
React 18 for the UI, Tailwind CSS for styling, and Recharts for the progress graphs. No backend required: all data is stored in the browser using localStorage. The app works fully offline after the first load.
 
## Configuration
 
The app reads a small config from `src/config.js`. You can change the default weight unit (kg vs lbs), the start day of the week, and which muscle groups appear in the exercise picker. No environment variables are required for the basic setup.
 
## Deployment
 
Because there is no backend, you can deploy the `build` output to GitHub Pages, Netlify, Vercel, or any other static host with no extra configuration. A `CNAME` file is not included by default; add one if you are using a custom domain with GitHub Pages.

## Known Limitations
 
Data lives in the browser. If a user clears their site data or switches to a different browser, their history is gone. The roadmap below covers a proper persistence layer.
 
## Roadmap
 
The items below are planned improvements in rough priority order. Pull requests are welcome for any of them.
 
Account system with cloud sync so data survives browser clears and is accessible across devices. This is the single most-requested feature and will require a lightweight backend, likely a Node/Express API with a Postgres database or a Firebase project.
 
Export to CSV and JSON so power users can pull their data into spreadsheets or third-party tools.
 
Apple Health and Google Fit integration for two-way sync with the device health store.
 
Rest timer with customizable durations that persists across sets during an active workout session.
 
Progressive overload suggestions that look at your recent performance for a given exercise and recommend a target weight or rep range for the next session.
 
Workout templates so you can save a routine once and start it in one tap rather than rebuilding it from scratch each time.
 
Social sharing cards, autogenerated images that summarize a workout or a milestone, suitable for posting to Instagram or Twitter.
 
Dark mode is already the default; a light mode toggle is a small but frequently requested UI addition.
